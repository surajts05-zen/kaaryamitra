Claude Implementation Prompt
Meetings & Calendar Manager for Multi-Tenant HRMS
Paste the prompt below into Claude Code/Coding Agent after giving it access to the existing HRMS repository. Claude should inspect and reuse the existing architecture rather than rebuilding the HRMS.
You are a senior SaaS architect and full-stack engineer working on an existing modern multi-tenant HRMS/HRM application.

Your task is to design and implement a first-class Meetings & Calendar Manager that integrates deeply with the existing HRMS.

IMPORTANT:
- Do NOT rebuild the HRMS.
- First inspect the existing repository and architecture.
- Reuse existing authentication, tenant isolation, RBAC, users/employees, departments, notifications, documents/files, tasks/projects, audit logging, workflows, email infrastructure, settings, UI components and design system.
- Do not duplicate existing infrastructure.
- Preserve all existing functionality.
- Do not introduce destructive database migrations.
- Implement incrementally, test each stage, and keep the application production-ready.
- Every meeting-related object must be tenant-isolated and permission-checked server-side.

============================================================
1. PRODUCT VISION
============================================================

Create a professional Meeting Manager where a meeting is a complete business object rather than merely a calendar event.

Core lifecycle:
Scheduled → Confirmed → In Progress → Completed → Minutes Pending → Minutes Published → Action Items Pending → Closed

Central workflow:
Meeting → Agenda → Notes → Decisions → Action Items → Minutes of Meeting (MoM) → Distribution → Follow-up → Closure

Use Google Calendar/Notion/Linear/Slack-style UX only as inspiration; do not copy proprietary UI.

FINAL PRODUCT PRINCIPLE:

"Meetings are not calendar events. Meetings are business workflows."

The experience should make it effortless to move from:
Schedule → Prepare → Meet → Capture → Decide → Assign → Document → Communicate → Follow up → Close.

Build this as a deeply integrated HRMS capability, not an isolated calendar widget.
