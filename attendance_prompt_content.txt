Do NOT try to prevent every possible form of attendance fraud by making attendance difficult.
Instead:
Make normal attendance extremely easy.
Validate the punch against the employee's assigned shift.
Validate the punch against organization policies.
Collect appropriate contextual evidence.
Detect anomalies.
Provide legitimate exception workflows.

55. FINAL IMPLEMENTATION PRINCIPLE
The finished product should feel like:
"Press one button and you're done."
while the backend behaves like:
"Every attendance event is validated, contextualized, auditable and difficult to manipulate."
The employee should NOT feel that they are using a surveillance system.
The administrator should feel that the organization has:
reliable attendance
clear evidence
configurable policy
controlled exceptions
auditability
fraud/anomaly visibility
payroll-ready records
Build the system so that normal employees experience almost zero friction, while suspicious or exceptional attendance automatically receives additional scrutiny.
Before writing implementation code, first produce:
Architecture
Data model
Attendance state machine
Policy engine
API contracts
Mobile capability abstraction
Desktop network validation architecture
Security/threat model
Failure-mode strategy
Test plan
Then implement each phase incrementally.
Do not make architectural assumptions that prevent a future migration from Capacitor to native Android.
